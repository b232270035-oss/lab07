## Гол дүгнэлт

Supermodel аяллын хүрээнд хэрэглэгчийн интерфейс болон үндсэн үйлдлүүдийг шалгаж, нийт номын тоолуур, оны формат, хайлтын ажиллагаа, `/old` холбоос, устгах товчны өнгө болон давхардсан ном нэмэгдэх зэрэг асуудлыг илрүүлсэн.

Couch Potato аяллаар хоосон болон дутуу талбар, зөвхөн зай агуулсан оролт, жилийн хязгаараас давсан болон бүхэл бус утгуудын баталгаажуулалт хангалтгүй байгааг шалгасан.

Saboteur аяллаар буруу JSON хүсэлтэд 200 статус буцах, буруу жилийн өгөгдөл хадгалагдах, ижил ном давхардах, JSON `null` утгаас шалтгаалан server ажиллахгүй болох зэрэг API түвшний асуудлыг шалгасан.

Тестийн явцад шинэ өгөгдөл нэмэх бүрд хэрэглэгчийн интерфейс дэх жагсаалт, `/api/books` болон `/api/stats` мэдээллийг хооронд нь харьцуулан шалгах нь үр дүнтэй байв.

Мөн charter-ийн үндсэн чиглэлээс гадуур устгасны дараах буруу мэдэгдэл, урт гарчгийн layout overflow, HTML entity давхар escape болох зэрэг асуудлууд илэрсэн.

Энэ session-д concurrent request, keyboard-only accessibility болон өөр browser engine-үүдийн ялгааг шалгаагүй. Иймээс дараагийн тестийн session-д эдгээр чиглэлийг хамруулах боломжтой.

Илрүүлсэн согогуудыг Playwright автомат тестээр дахин шалгаж болно. Тухайлбал, жагсаалтын мөр болон статистикийн тоо, оны формат, required-field validation, хайлтын ажиллагаа, давхардсан өгөгдөл болон `/old` холбоосын HTTP статусыг автоматжуулан шалгах боломжтой. API-ийн буруу payload болон `null` утгын асуудлыг API түвшний тестээр шалгаж болно.

Exploratory testing нь урьдчилан тодорхойлсон тестийн тохиолдлоос гадна системийн бодит хэрэглээний явцад гарч болох асуудлуудыг илрүүлэхэд үр дүнтэй болохыг энэхүү session-ээр ойлгож авлаа.
